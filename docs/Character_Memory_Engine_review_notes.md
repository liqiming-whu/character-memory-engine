# Character Memory Engine 最新源码与文档审查总结

> ⚠️ **状态更新（2026-08-06）**：本文为审查阶段结论。v2.1.2 mount 实验已实锤根因（详见 `docs/INIT_RACE_ROOT_CAUSE_AND_FIX_PLAN.md`）：核心不是"多状态源"设计问题，而是 **Operit JS 模块重载 + 工具调用第二层初始化竞态（约 2/3 概率返回空壳）+ useState 持久化部分失效 + 空结果覆盖**。本文"状态机化 / 区分 null 与 [] / 统一状态管理"等建议仍有效，作为修复方案参考，但实施顺序以根因文档为准。

## 版本背景

本文基于当前 Character Memory Engine 最新源码与开发文档审查结果整理。

目标：

-   记录当前架构状态
-   总结已验证正确的设计
-   标记存在的问题
-   提供后续优化建议

# 二、Worker启动架构问题

## 当前现象

发现：

-   ensureWorkerUp 无延迟调用时，会稳定触发 worker 无法自动拉起问题。
-   增加启动延迟后问题解决。
-   用户进入插件时，即使启动后数秒进入，也可以正常触发 worker。

## 判断

30秒延迟不是 worker 启动耗时。

更可能是：

Operit 启动阶段 terminal.hiddenExec / proot executor 初始化竞态。

问题链：

Operit启动

↓

executor 尚未稳定

↓

hiddenExec过早调用

↓

worker启动失败

------------------------------------------------------------------------

## 修改建议

不要简单删除延迟。

当前方案：

-   保留启动保护机制。

长期优化：

增加 Runtime 状态检测：

阶段：

    OPERIT_STARTING

    ↓

    EXECUTOR_READY

    ↓

    WORKER_STARTING

    ↓

    WORKER_READY

    ↓

    ENGINE_READY

注意：

health check 不能替代 executor 初始化保护。

正确关系：

启动保护

↓

hiddenExec安全

↓

worker health check

↓

engine ready

------------------------------------------------------------------------

# 三、前端主要问题

## 1. 多状态源导致竞态风险

当前：

screen.js 管理：

-   persona
-   memories
-   loading

character.js 又管理：

-   persona
-   memories
-   context loading

存在：

同一数据多个来源。

风险：

    screen加载完成

    ↓

    character内部状态仍为空

    ↓

    显示未识别角色

    ↓

    重新进入或切tab恢复

符合当前偶发问题表现。

------------------------------------------------------------------------

## 修改建议

增加统一状态中心：

例如：

MemoryController

负责：

-   worker状态
-   当前角色
-   记忆缓存
-   loading状态
-   error状态

页面只负责展示。

------------------------------------------------------------------------

# 四、加载状态设计问题

## 当前风险

存在：

-   未识别角色卡
-   正在读取
-   读取失败
-   空白页面

但是实际原因可能不同：

-   worker未启动
-   executor未准备
-   数据加载中
-   请求失败
-   状态未同步

------------------------------------------------------------------------

## 修改建议

增加明确状态：

    INITIALIZING

    WORKER_STARTING

    WORKER_READY

    LOADING_DATA

    READY

    EMPTY

    ERROR

不要使用单一 loading 布尔值。

------------------------------------------------------------------------

# 五、空数组状态问题

发现潜在问题：

部分同步逻辑使用：

    array.length > 0

判断是否有效。

问题：

空数组可能表示：

"已加载但没有数据"

而不是：

"未加载"。

建议：

区分：

    null
    =
    未加载

    []
    =
    已加载但为空

避免旧缓存残留。

------------------------------------------------------------------------

# 六、自动分析任务竞争

当前：

进入界面后可能同时：

-   加载角色数据
-   加载记忆
-   触发分析任务

风险：

worker刚启动时：

    UI请求

    +

    分析请求

    +

    数据库初始化

产生竞争。

------------------------------------------------------------------------

## 修改建议

调整顺序：

    worker ready

    ↓

    加载UI数据

    ↓

    空闲后执行分析

------------------------------------------------------------------------

# 七、旧UI模块清理

发现仍存在：

-   todos
-   contacts
-   messages

这些来自旧 Character Memory System。

当前 Engine 定位：

角色记忆引擎。

这些模块：

-   增加状态复杂度
-   增加初始化路径
-   增加维护成本

建议：

移除或独立。

------------------------------------------------------------------------
